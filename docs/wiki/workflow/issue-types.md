# 条目类型与复现步骤（强制）

索引：[agents-workflow.md](agents-workflow.md)

## 类型按「现在有没有这个行为」判

- `bug`：行为**已实现**但与原生／预期不一致（可复现，必须能写 `## Steps to Reproduce`）；
- `task`：行为**尚未实现**（功能缺失、未接线、未导出、未取证）；
- `chore`：重构、命名、建模、文档、工具，不改变可见行为；
- `feature`／`epic`：新增能力与容器。

不许因为「读起来像错误」就判 bug，也不许因为「需要改代码」就判 task。

## `bug` 必须带 `## Steps to Reproduce`

`bd lint` 与 `issue-bug-repro-steps` 对 `bug` 类型强制。写法固定四行：
`起点`（地图／页面／存档／战斗第几回合）→ `操作序列`（按顺序，一步一个动作）→ `期望` → `实际`。
每一步都要能被别人照做（界面操作、触控/按键、命令或存档位置），**不许写「偶发」「有时」「多试几次」**。

**没复现过的不是 bug**：先建 `task` 做取证／调查，复现成立后再改类型并补齐复现步骤。
复现步骤可以是用户提供，也可以是代理实测——代理实测时必须注明「已实测」并附实际走过的路径。
